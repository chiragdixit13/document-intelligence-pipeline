
Document Intelligence & Decision Pipeline


An invoice-processing dashboard that connects a frontend to a FastAPI
backend, extracts invoice information from PDF files using your
processing pipeline, stores invoice records in PostgreSQL, and supports
human approval or rejection.

Important: Set up the backend and database first
The frontend does not create the database or process invoices by
itself. Before using the dashboard, make sure your FastAPI backend and
PostgreSQL database are configured and running.

1. Create the PostgreSQL database
Open pgAdmin → Query Tool and run this command if you have not
created the project database yet:

CREATE DATABASE invoice_intelligence;
If the database already exists, do not run the command again. Select the
invoice_intelligence database in pgAdmin and open its Query Tool.

2. Create the invoices table
Run the following SQL inside the invoice_intelligence database:

CREATE TABLE IF NOT EXISTS invoices (
    invoice_id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    invoice_number VARCHAR(100) NOT NULL,
    vendor VARCHAR(255) NOT NULL,
    amount NUMERIC(12, 2) NOT NULL,
    tax NUMERIC(12, 2) NOT NULL,
    total NUMERIC(12, 2) NOT NULL,
    validation_status VARCHAR(50) NOT NULL DEFAULT 'pending',
    approval_decision VARCHAR(50) NOT NULL DEFAULT 'pending',
    approval_level VARCHAR(100),
    reviewed_by VARCHAR(100),
    reviewed_at TIMESTAMP,
    reason TEXT,
    evidence JSONB,
    file VARCHAR(255),
    processed_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE UNIQUE INDEX IF NOT EXISTS uq_invoices_vendor_number
ON invoices (vendor, invoice_number);
If you already have an invoices table: inspect its columns before
applying this SQL. CREATE TABLE IF NOT EXISTS does not add missing
columns or change an existing table. Do not drop an existing table
because it may contain invoice data. Your backend's SQL statements and
the table schema must use matching column names.

3. Configure the FastAPI backend
In your backend project, configure the database connection using
environment variables. For example, create a .env file in the backend
folder:

DB_HOST=localhost
DB_PORT=5432
DB_NAME=invoice_intelligence
DB_USER=postgres
DB_PASSWORD=YOUR_POSTGRES_PASSWORD
Use the variable names your backend code actually reads. Never commit
.env or real passwords to GitHub. Add .env to .gitignore.

Make sure the backend has its required dependencies installed, including
FastAPI, Uvicorn, psycopg, python-dotenv, and the PDF/LLM libraries used
by your implementation.

Start the backend from the folder containing api.py:

uvicorn api:app --reload
The local API should be available at:

API root: http://127.0.0.1:8000
Invoice list: http://127.0.0.1:8000/invoices
Interactive API docs: http://127.0.0.1:8000/docs
Open /invoices and verify it returns a JSON array with separate fields
such as invoice_id, invoice_number, vendor, total, and
approval_decision before connecting the frontend.

4. Connect the frontend to FastAPI
Open script.js and set API_URL to your backend URL:

const API_URL = "http://127.0.0.1:8000";
For local development, this is correct when FastAPI runs on your
computer.

For deployment, replace it with the deployed FastAPI service URL,
for example:

const API_URL = "https://YOUR-BACKEND-SERVICE.onrender.com";
Replace the example URL with your real backend URL. Do not include
/invoices at the end; the frontend adds endpoint paths itself.

Your FastAPI app must provide these endpoints:

GET /invoices --- list invoices.
POST /upload_pdf --- upload and process a PDF.
POST /invoices/{invoice_id}/review --- approve or reject an
invoice.
If the frontend and backend run on different origins, configure FastAPI
CORS to allow the frontend's exact origin. For local VS Code Live
Server, that may be http://127.0.0.1:5500 or http://localhost:5500,
depending on the address shown in your browser. For deployment, allow
your actual frontend domain.

5. Run the frontend
Keep PostgreSQL running.
Start FastAPI and confirm /invoices works.
Open the frontend folder in VS Code.
Use Live Server to open index.html, or serve the frontend using
your chosen static hosting service.
Refresh the page and confirm the dashboard reports that the API is
connected.
Upload a sample PDF and check the FastAPI terminal if processing
fails.
6. Deployment order
Deploy in this order:

PostgreSQL: create or provision a hosted database.
FastAPI backend: configure its database environment variables
and deploy the API.
Frontend: set API_URL in script.js to the deployed backend
URL and deploy the static frontend.
CORS: allow the deployed frontend origin in FastAPI.
Test: open the deployed API /invoices endpoint, then test
listing, uploading, and reviewing invoices in the frontend.
For a hosted PostgreSQL database, use the provider's connection details
rather than localhost. Keep database credentials in the backend
hosting provider's environment-variable settings; never place them in
frontend JavaScript.

Troubleshooting
API unavailable / CORS error: verify the backend URL, that the
service is running, and that CORS allows the frontend origin.
Upload fails: inspect the FastAPI terminal logs and the
browser's Developer Tools → Network → upload_pdf → Response.
Invoice is not saved: verify the PDF extraction/LLM result and
the database insert error in the backend logs.
Database column error: compare the SQL schema with the column
names used in api.py.
Duplicate invoice: the unique index prevents saving the same
vendor and invoice number twice. Adjust the uniqueness rule only if
your business logic requires something different.
Security notes
Never put PostgreSQL credentials in script.js or any frontend
file.
Do not commit .env files or API secrets to GitHub.
Use HTTPS for deployed services.
Configure CORS for specific trusted frontend origins rather than
allowing every website in production.
This README is a setup guide. Your exact environment-variable names,
database schema, dependency list, and hosted URLs must match the backend
implementation you deploy.
